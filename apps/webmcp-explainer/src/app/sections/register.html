3 · The page registers a tool

This is ~90% of WebMCP. The page describes one capability: a name, a description the agent uses to decide when to call it, a JSON Schema for the arguments, and an execute callback — plain app code. 

document.modelContext.registerTool({
  name: 'increment',
  description: 'Increase the page counter by a given amount.',
  inputSchema: {
    type: 'object',
    properties: {
      amount: { type: 'number', description: 'How much to add. Defaults to 1.' },
    },
  },
  execute: ({ amount }) => {
    counter.increment(amount ?? 1, 'agent');
    return { content: [{ type: 'text', text: `Count is now ${counter.count}.` }] };
  },
});

Registered. The browser now holds this tool for the lifetime of the page (or until the page aborts an AbortSignal it passed at registration). Nothing visible changed for humans — tools are a parallel entrance, not UI.
