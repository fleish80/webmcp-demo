1 · The problem

Without WebMCP

agent → screenshot / DOM → guess a selector → move mouse → click → hope

  • Slow: many round-trips per action
  • Fragile: any redesign breaks the agent
  • Blind: the agent infers meaning from pixels

With WebMCP

agent → increment({ amount: 5 }) → done

  • One call, typed arguments, structured result
  • Survives redesigns: tools are an API, not pixels
  • Runs your real app code, in the user's own session
